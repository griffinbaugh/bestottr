# BestOttr maintenance

- The owner requires independence from Lovable. Use local code changes, GitHub, Cloudflare Workers, the owner-controlled Supabase project, and Resend. Do not use a managed editor agent for implementation or reintroduce editor-specific build/runtime dependencies.
- Preserve published Git history. Never force-push or rewrite it.
- The backend migration is not complete until existing tickets are copied and verified in the owner-controlled Supabase project. Keep exports and credentials out of Git.

- Keep seller listing prices in integer cents through the shared CurrencyInput and convert only when creating a listing; verified financial metrics retain their existing input model.
- Keep auction scheduling in the shared auction-end helpers, validate again at publication, and store absolute millisecond timestamps so countdowns remain independent of display modes.
- Treat bestottr.com (root) as the canonical hostname with www redirecting to it, so generated metadata, canonical/OG URLs and share links point at the canonical host rather than a preview host; while the domain is not yet live, use the Cloudflare workers.dev URL.
- Support tickets are created only through the security-definer `submit_support_ticket` RPC (called from a server function with validation + honeypot); the table has no public insert/select, and admin reads/updates are gated by `has_role(..., 'admin')` RLS. Why: public users must never enumerate tickets.

- Support ticket emails send through Resend (RESEND_API_KEY, direct HTTPS API) via `deliverTicketEmails` in `src/lib/support-email.server.ts`; inbound support@ stays on Cloudflare Email Routing. Why: the owner chose Resend for outbound.

- Experience galleries use ordered source-tagged entries and a shared cover resolver; legacy image-only listings normalize at read time. Why: preserve existing marketplace assets and stable listing IDs.
- Public Roblox metadata is fetched through a server function only after the separate strict demo ownership verifier passes; metadata never authorizes ownership. Why: avoid CORS without weakening verification.
- The demo marketplace keeps uploaded images in IndexedDB behind a replaceable media adapter and stores durable references in its existing local listing state, not object URLs. Why: persist uploads across reloads without implying hosted or cross-device storage.
- Experience edits pass through a field allowlist and the demo current-seller check; IDs, seller, verified identity, bids and status remain immutable. Why: update an existing listing without changing its ownership or public link; production account authorization remains outside this demo marketplace.
- Experience deal money movement goes only through the pure transfer engine (`src/lib/transfer.ts`) and the PaymentProvider interface; UI/store actions never release or refund directly. Why: payout must follow verified Roblox ownership, exactly once. The demo monitor runs client-side from persisted timestamps; production must run the same engine in a server scheduler.
- Community banners come from a best-effort server-side public Community page extractor (`src/lib/community-page-media.ts`), restricted to https Roblox/rbxcdn hosts; the official thumbnails API stays the icon source, and page data never changes identity/owner. Why: Roblox has no documented banner API.
- Community banner/icon geometry (icon bottom-aligned inside the banner) lives only in the shared `CommunityBanner` component. Why: consistent card/detail/preview composition.
- Self-hosting on Cloudflare deploys the standard build output with root `wrangler.jsonc` (adds nodejs_compat); see MIGRATION_CLOUDFLARE.md. Why: generated dist/server/wrangler.json lacks required flags.

- Email authentication callbacks are processed explicitly by `completeEmailCallback`; keep browser `detectSessionInUrl` disabled through `EMAIL_AUTH_OPTIONS`. Why: SDK auto-initialization and explicit callback exchange can race to consume a single-use PKCE code. Preserve flow IDs and recovery destinations.

- Production `/sell` uses private database-backed drafts. Every save authenticates and derives Roblox identity from the linked account. The draft-only request gate combines simultaneous checks and may reuse a successful check for the same linked user/asset for at most 15 seconds, preserving its original checked-at timestamp. Once expired, require a new live lookup; never serve expired success after a failure. Honor provider rate-limit cooldowns server-side and in the editor. Never reuse demo ownership/metadata fallbacks or client-provided identity. Publication and money movement must use a fresh authoritative check outside this draft-only gate.

- Cloudflare Workers does not support fetch `redirect: "error"`. Use `redirect: "manual"` and reject non-2xx responses when redirects are forbidden. Verify ownership-request changes with `node scripts/check-listing-ownership-worker.mjs`; a build/dry run alone does not execute runtime request construction.

- Private experience drafts resolve the place to its universe, then read `develop.roblox.com/v1/universes/{universeId}` for `creatorType` and `creatorTargetId`; the games/v1 endpoint can return zero-ID content-restricted placeholders. Match the returned universe ID and validate positive IDs; group ownership still requires the group's current `owner.id` (with `owner.type` equal to `User`) from `groups.roblox.com/v2/groups?groupIds=…` to match the OAuth-linked user. A private/inactive experience is not evidence of missing ownership.

- Production draft media lives in private `bestottr-draft-images` and `bestottr-draft-files` buckets. Every media action verifies the account/MFA and server-derived seller before privileged access. Upload slots are reserved with a service-only, SECURITY INVOKER RPC that serializes account quotas; use non-upsert signed uploads and validate actual size/MIME plus image signatures before marking ready. Never sign deliverable file links in previews; seller downloads are short-lived attachments. No buyer entitlement is implied by a draft upload. File drafts must have null Roblox ownership fields. Keep publication/checkout disabled until an approved provider and authoritative payment/fulfillment integration exist.

- Trustap is the chosen protected-payment provider. Its implementation is sandbox-only, fixed to api.test.trustap.com and test OAuth/hosted-payment origins. Never enable live money or introduce invented complaint-period/release parameters. Trustap account settings determine the actual release deadline; no extra BestOttr ownership inspection timer is used. Confirm Roblox delivery only after a fresh exact-asset ownership proof for the pinned buyer, a fresh validated provider payment, and the serialized order lease. File receipt requires the buyer's explicit confirmation; downloads alone do not confirm delivery. Only server-verified OAuth identities may populate participant IDs. Do not store OAuth tokens or accept IDs from browser forms. Webhook Basic credentials must be checked, event bodies are hints only, and durable pending records plus scheduled/manual GET reconciliation recover missed notifications. Never blindly repeat uncertain transaction creation; reconcile an existing dashboard transaction ID against the pinned description/parties/amount. Legacy Escrow.com tables are retained solely as migration history and are not used by this integration.

- Production listing moderation freezes a saved draft and copies private attachments into `bestottr-review-assets`. Never edit an active reviewed draft or reuse an old approval for changed content. Use service-only version-checked review RPCs and database admin roles, preserve audit history, and require fresh authoritative Roblox ownership again at publication. `LISTING_PUBLICATION_ENABLED` defaults false; enabling it exposes only approved, separately published fixed-price versions through server-allowlisted data and an uncached image proxy. Deliverables remain private; approval/publication never enables checkout, bidding or buyer delivery. Auctions stay unpublished until authoritative bidding/settlement exists.

- Production Buying, Selling and private order routes read verified account data, never demo state. Lists derive buyer/seller filters from the verified session; order details must pass the participant check before private history/files are serialized, even for admins. Keep sandbox amounts explicitly labeled as test values, preserve the existing Trustap action gates, and do not treat a stale displayed status as funding or payout authorization. Experience/community delivery is ownership transfer; a deliverable file is required only for downloadable-project listings.

- In-app listing-decision notifications are inserted atomically by `private.notify_listing_decision` on review events, using the service caller and source-event uniqueness. Never create notifications from browser-supplied recipients/content or send email as a side effect of this feature. Reads and read-status changes derive the recipient from the verified session/MFA; authenticated SQL clients may update only their own `read_at` column. Opening the bell does not mark everything read; mark-all is bounded to the fetched timestamp so chronologically later events remain unread. In-app notifications are independent of email preference settings.
